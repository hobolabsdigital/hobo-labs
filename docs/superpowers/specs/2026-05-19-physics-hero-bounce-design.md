# Physics Hero Bounce Fix Design

## Objective
Fix the backward-bouncing bug for dynamically spawned hero nodes on the ReactFlow editorial canvas.

## Context
When a new node is generated by the AI (e.g., a text node followed by a hero node), the hero node sometimes bounces violently to the left side of the canvas (near node 1 or 2) instead of seamlessly taking its place at the end of the timeline (the right side).

## Root Cause Analysis
In `src/features/canvas/hooks/useEditorialPhysics.ts`, the `x-flow` force has logic to pin the initial `hero` and `intro` nodes by explicitly excluding them from the linear left-to-right current:
```typescript
// Push each subsequent node further right based on creation order
if (d.type === 'hero' || d.type === 'intro') return d.x ?? 0;
```
This inadvertently catches *all* hero nodes, meaning dynamically spawned hero nodes do not receive the `x-flow` force that keeps them at the right end of the timeline. Without this force, the many-body charge (repulsion) from the other clustered nodes pushes the new hero node backward to the empty space on the left.

## Implementation Plan
Modify the `x-flow` exclusion condition in `useEditorialPhysics.ts` to only apply to the initial hero node (`hero-1`), not all hero nodes.

```typescript
// The first hero node and intro node are pinned — don't apply x flow force
const isInitialHero = d.type === 'hero' && d.id === 'hero-1';
if (isInitialHero || d.type === 'intro') return d.x ?? 0;
```

This ensures that any dynamically generated hero node will respect its `creationIndex` and be pulled into its correct linear position at the end of the queue.

## Testing & Validation
- Spawn a standard Project/Text node (it should go to the right).
- Spawn a Hero node (it should follow the previous node to the right and not bounce left).
- Verify the initial `hero-1` node remains pinned.
