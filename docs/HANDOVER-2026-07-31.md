## NEXT TASK (user-approved): AI chat context management

**Goal:** when the chat context fills, archive the conversation as an *epoch* and reset, carrying a summary into the fresh context for fluidity; history stays browsable on a timeline.

**Decided by user (2026-07-31):**
- Reset scope: **Archive nodes with epoch** — canvas clears; each epoch stores its nodes+messages; browsing an old epoch restores that view read-only; new context is seeded with a summary.

**Open question — ASK THE USER FIRST:**
- Where does epoch history live in the UI? Options discussed: (a) extend the existing TimelineScrubber with "chapters" (most integrated; mobile gets a compact strip), (b) left rail panel, (c) bottom bar above the chat input. User deferred this decision to next session.

**Architecture map (verified against code, full version in ruflo memory `handover/context-management-map`):**
- Chat messages live ONLY in AI SDK `useChat` (`src/features/editor-chat/hooks/useEditorialChat.ts:37`) — no zustand chat slice. Mutation seam: `setMessages` (already used for time-travel at `:166`).
- Context meter is cosmetic: `messages.length` vs hard-coded `maxContext = 20` in `ChatInput.tsx:19-27`; NOTHING happens at 100%. Real caps are server-side (40 msgs / 32KB → 400/413 the UI doesn't handle).
- TimelineScrubber "turns" are **canvas node array indices**, not messages; scrubbing = visibility filtering (`EditorialCanvas.tsx:63-112`). Epochs-as-index-ranges works IF archived nodes stay in the array; a clearing reset needs an `epochs[]` slice + scrubber changes.
- Only existing reset-like action: `truncateHistory(cursorIndex)` (`nodeActionSlice.ts:221-237`) — shows the exact transient fields an archive action must null (`activeGhostId`, `activeStreamingTextId`, `timeCursor`, `lastPlacedNodeId`).
- Summarization: copy the non-streaming `generateText` pattern from `src/app/api/project-context/route.ts` (Ollama Cloud ignores structured-output protocol — use plain text). `ollamaClient`/`createModel` in `src/lib/ai/config.ts`.
- Persistence: **none exists anywhere** (no localStorage/persist middleware). Epoch archive is the first persistence — free choice of mechanism.

**Landmines (from code, don't skip):**
1. Prompt-count↔message-index correlation (`useEditorialChat.ts:150-166`) is the ONLY canvas↔chat mapping; an injected summary message that isn't accounted for breaks time-travel cut math.
2. Node ids for hero/project/contact ARE AI-SDK toolCallIds — never assume regenerable.
3. `timeCursor` is an array index — any splice shifts scrubber/canvas/mobile visibility semantics.
4. `hasInitialized` ref suppresses re-greeting after `setMessages([])`; server fast-path `isInitialGreeting` fires on any 1-message "Introduce yourself" history — decide seeding explicitly.
5. Mid-stream reset needs `stop()` from useChat.
6. `MobileStreamView.tsx` nodeTypes map lacks `contact` (drifted from desktop) — any new epoch-marker node type must be added to BOTH maps.
7. Layout origin never resets (`calculateNodePosition` grows rightward forever); clearing nodes resets it for free.
8. Rate limiter: an extra client-hit summarize call counts against the same 30/10min window; a server-internal call doesn't.
