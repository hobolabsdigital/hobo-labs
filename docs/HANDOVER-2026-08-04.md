## Shipped this session: AI chat context management (epochs)

Commits `02244e4` (feature) + `272b2b9` (UX fix). Both live-verified in Chrome end-to-end.

**Behavior:** at `ARCHIVE_THRESHOLD` (20 messages) nothing happens — the conversation stays readable, meter at 100%. On the visitor's **next send**, the conversation + canvas archive into an epoch ("chapter"): `/api/summarize` writes a ≤180-word summary, the canvas clears (layout origin resets), the summary reseeds the fresh context as a **system-role** message, and the new prompt opens the new chapter. Chapters are browsable read-only via markers at the foot of the TimelineScrubber (desktop) or a chip strip above the input (mobile). "Return to present" resumes live state. Composing is blocked while archiving/viewing.

**Map:**
- `src/features/canvas/store/slices/epochSlice.ts` — `Epoch {id,index,title,summary,nodes,edges,messages,endedAt}`, `epochs[]`, `viewingEpochId`, `isArchiving`, `archiveEpoch` (snapshots then clears all ten transient fields in one set()). Epoch title = first real visitor prompt (skips the auto-sent "Introduce yourself.").
- `src/features/editor-chat/hooks/useEditorialChat.ts` — `archiveConversation` + threshold check **inside `sendPromptText`** (NOT an effect — that was the original design and it yanked the last reply away mid-read; don't regress this). Summarize failure falls back to a client-built summary; archiving is never blocked by the API.
- `src/app/api/summarize/route.ts` — rate-limited, zod-validated, plain-text `generateText` (no structured output — Ollama Cloud ignores that protocol), 24KB transcript cap, 200 `{summary}`.
- UI: `TimelineScrubber.tsx` (chapter stack, drag range shrinks by `chaptersHeight`), `EditorialCanvas.tsx` (epoch view swaps node/edge source, change handlers detached while viewing), `ChatInput.tsx` (real meter, `bg-primary` fix, mobile chips), `MobileStreamView.tsx` (epoch snapshots + previously-missing `contact` nodeType).

**Invariants that must hold (learned the hard way):**
1. The context seed MUST be role `system` — the time-travel branch-cut math counts `role === 'user'` messages against prompt nodes; a user-role seed breaks it. `ai@6.0.176` `convertToModelMessages` handles system UIMessages (case at dist/index.mjs:8399).
2. The text-node streaming effect guards on `role === 'assistant'` — loosening it makes the seed spawn a text node on the fresh canvas.
3. The seed counts against `/api/chat`'s `MAX_MESSAGES=40` / 32KB caps — fine at threshold 20, re-check if it's ever raised.
4. No persistence: epochs are in-memory, same as chat itself. localStorage persistence is a clean future add (epochs are already serializable-ish, but node data contains toolCallId-keyed content — verify before assuming).
